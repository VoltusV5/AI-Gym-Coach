## Запуск и проверки

Выполните команды из каталога `frontend`.

```sh
npm ci
npm run verify
npx playwright install chromium
npm run test:e2e
npm run dev
```

`verify` выполняет lint без исправлений, модульные тесты и production-сборку. Vite открывает приложение на порту 5173 и проксирует API к Go на `127.0.0.1:5050`. Контрактные тесты Playwright запускают свой Vite на порту 55173. В CI выполняются те же проверки и контрактные браузерные сценарии.

Для `real.spec.js` нужен локальный Go с отдельной одноразовой БД. Примените к ней миграции backend, создайте синтетических пользователей с ролями `user`, `trainer`, `admin` и второго `user` для проверок отказа доступа. Заполните каталог через `catalog-seed` с ID тренера. Передайте значения через переменные окружения.

```sh
SPORTIK_REAL_E2E=1 \
  SPORTIK_E2E_MEMBER_EMAIL='<member>' SPORTIK_E2E_TRAINER_EMAIL='<trainer>' \
  SPORTIK_E2E_ADMIN_EMAIL='<admin>' SPORTIK_E2E_OTHER_EMAIL='<other>' \
  SPORTIK_E2E_PASSWORD='<test-password>' npm run test:e2e -- real.spec.js
```

Замените значения в угловых скобках на реквизиты синтетических пользователей. Для теста генерации запустите ML v2 или его контрактную фикстуру, затем добавьте `SPORTIK_E2E_ML=1`. Для локальной записи теста можно включить `SPORTIK_E2E_VIDEO=1`. Подготовка Go и миграций описана в [правилах backend](../../backend/AGENTS.md).

## Результаты приёмки

- `npm run verify` — lint, 6 модульных тестов и production-сборка прошли.
- Playwright — 16 сценариев прошли. Тринадцать на контрактных фикстурах, три на Go с отдельной PostgreSQL 18 и синтетическими данными. Сценарий генерации использовал контрактную ML-фикстуру за реальным Go API.
- `make -C backend verify` — форматирование, vet, Go-тесты и сборка прошли.
- Каталог проверен в Chromium на 390 и 1440 px. Горизонтальной прокрутки и ошибок JavaScript на этих экранах нет. Независимое ревью проверило изоляцию сессий и конфликтные сценарии.

## Демонстрация

1. Откройте каталог, задайте цель «Набрать мышцы» и откройте бесплатную программу. Войдите, нажмите «Получить бесплатно» и перезагрузите страницу. Состояние «Программа доступна» приходит с сервера.
2. Откройте профиль и сохраните дробный вес. Создайте план, добавьте упражнение, привяжите день к расписанию и активируйте план. Введите 8 повторений с весом 12,5 кг. На экране результата рабочий объём равен 100 кг.
3. Войдите тренером, подайте заявку и отправьте авторский черновик на модерацию. В отдельной сессии администратора примите решения. Убедитесь, что профиль показывает отметку подтверждения, а обновление опубликованной программы открывает отдельную версию.

## Границы

- Go возвращает статус отклонения авторской программы. Текст причины остаётся в серверном аудите и не входит в ответ программы. Интерфейс показывает текст при наличии поля `moderation_reason`. Для тренерской проверки причина уже приходит из API и показывается.
- Старые локальные кэши заметок и тренировок без идентификатора владельца сохранены в браузере. Экран читает только кэш текущего аккаунта. Серверные заметки заново загружаются из Go.
- Пагинация заметок использует существующие `limit` и `offset` API v1. Клиент скрывает дубли при параллельных изменениях списка. Пагинация новых списков использует курсоры Go.
- Документация функций сосредоточена на новом коде и изменённых контрактах. Сплошная инвентаризация JSDoc старых экранов и модулей ещё нужна.
