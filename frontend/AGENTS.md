# Фронтенд Спортика

Действуют также [правила репозитория](../AGENTS.md). Приложение использует Vue 3, Ionic Vue, Pinia и Vite. Код приложения на JavaScript, DTO документируются через JSDoc.

- `src/views/` содержит маршрутизируемые экраны, `src/views/v2/` — экраны API v2. Маршруты зарегистрированы в `src/router/`.
- Компоненты интерфейса и общие оболочки лежат в `src/components/`. Используйте `FeaturePage` для новых экранов и `RequestState` для загрузки, пустого состояния, ошибок, повтора и входа после 401.
- Pinia хранит общую сессию и состояние существующих сценариев. Черновик формы держите отдельно от ответа сервера. Данные отдельной тренировки в sessionStorage привязывайте к аккаунту.
- Используйте экземпляр Axios из `src/api/api.js` и функции `src/api/v2.js`. Проверяйте путь, поля, версию и ошибки по текущей реализации Go и [OpenAPI](../docs/02_API.md). Права на данные окончательно проверяет Go. Не логируйте заголовки, токены, поля профиля и документы проверки.
- Для чтения и списка применяйте отмену устаревших запросов. Блокируйте повторную запись, оставляйте ввод при сбое, покажите конфликт версий и предложите перечитать сервер. При истечении сессии предложите вход и возврат к экрану.

Выполните команды из `frontend/` с Node 24 LTS.

```sh
npm ci
npm run dev
npm run verify
npx playwright install chromium
npm run test:e2e
```

`npm run verify` проверяет lint без исправлений, модульные тесты и production-сборку. Vite по умолчанию проксирует `/api` к `127.0.0.1:5050`. Браузерные тесты используют контрактные фикстуры. Для реального Go запускайте только изолированную БД с синтетическими данными. Подробнее в [отчёте о проверке](docs/v2-frontend.md).

Перед правками определите план, модули и проверяемые сценарии. После реализации запустите целевые тесты и verify, передайте конкретный diff с контрактом отдельному ревьюеру, внесите исправления и повторите проверки. После 2–3 циклов без прогресса зафиксируйте препятствие и непроверенные условия.
